## 現況問題

截圖 06：點「+備註」輸入文字時系統鍵盤升起，出現三個問題：

1. 分類網格被擠成半截。
2. 數字鍵台被鍵盤蓋住一半。
3. 「記一筆」完全被鍵盤蓋住，輸入完備註還得先收鍵盤才找得到。

原因（已對照程式碼）：`AndroidManifest.xml` 沒有設定 `windowSoftInputMode`，版面是一串固定高度的元件加一個 `weight(1f)` 的分類網格。鍵盤出現後可用高度縮小，只有網格能縮，其餘固定高度的元件被推到鍵盤下面。

## 決定

系統鍵盤與自製數字鍵台不可能同時佔用畫面下半部，所以解法是：**編輯備註時，數字鍵台收起**。

1. 備註欄取得焦點（系統鍵盤出現）→ 數字鍵台隱藏（`AnimatedVisibility`，預設動畫）。
2. 分類網格、日期列、備註欄、「記一筆」都留在鍵盤上方，完整可見、不被壓縮。「記一筆」緊接在備註欄下方，不貼底。
3. 這個狀態下金額區縮小（金額字級 `amountInput` 54sp 縮為 40sp，其餘 token 不變），讓出高度。整個金額區可點：點下去清除焦點、收起鍵盤、數字鍵台回來，使用者即可修改金額。
4. 備註欄鍵盤動作鍵設為「完成」（`ImeAction.Done`）：按下清除焦點、收起鍵盤、數字鍵台回來，備註文字保留。
5. 備註欄失去焦點的其他途徑（返回鍵收鍵盤、點別處）行為相同。

高度預算（360×760dp；系統鍵盤約 273dp 加建議列，從畫面頂端算起約 487dp 以下；單位 dp，估算值，請實測）：

| 區塊 | 高度 |
|---|---|
| 狀態列 | 24 |
| 標題列 | 48 |
| 金額區（縮小） | 64 |
| 分類網格（2 列） | 156＋列距 4 |
| 日期／備註列 | 56 |
| 備註欄 | 56＋下距 8 |
| 「記一筆」 | 8＋52 |
| 合計 | 約 476，低於 487 |

鍵盤高度依裝置與輸入法而異。若實測放不下，壓縮順序：先縮金額區，再讓分類網格退回單列＋捲動（需露出半列提示，不是裁切）。

實作提示：整頁根容器用 `Modifier.imePadding()`，不要依賴 `adjustResize` 的隱含行為；「鍵台是否顯示」用備註欄的 `onFocusChanged` 或 `WindowInsets.isImeVisible` 擇一驅動，不要兩套並存。

狀態：

- 備註收合（預設）：沿用現況，數字鍵台顯示，「+備註」為未選取樣式。
- 備註展開且無焦點：備註欄顯示，數字鍵台顯示。
- 備註聚焦（本決策主體）：如上，數字鍵台隱藏。
- 備註欄樣式：`TextField` 單行，高 56dp，圓角 12dp，聚焦時 2dp `primary` 外框（UI-SPEC §5.4 只寫「單行 TextField」，這是補充）。
- 深色模式：沿用既有 token，無額外差異。英文介面：沿用同一版面。
- 載入中／空狀態／錯誤：不適用。

沿用 UI-SPEC 既有 token，**不新增 token**。

## 行為改變

使用者能做的事不變，資料不變，`TESTCASES.md` 沒有測案受影響。互動順序有變：輸入備註期間不能直接點數字鍵，要先收鍵盤或點金額。Maestro flow 目前在輸入備註後呼叫 `hideKeyboard`，新行為下 `hideKeyboard` 之後鍵台會回來，仍相容；若有 flow 在鍵盤開著時直接點數字鍵，會因鍵台隱藏而失敗，需重跑所有涉及備註的 flow 確認。

## 無障礙

- 金額區變成按鈕：高度 64dp ≥ 48dp，`Role.Button`，描述如上，TalkBack 才知道可以點。
- 備註欄外框 `primary`（dark `#D9673F`）對 `#000000` 約 6:1；備註文字 `onSurface` 約 21:1。
- 鍵台隱藏時，焦點順序：取消 → 支出/收入 → 金額 → 分類 → 日期 → 備註 → 記一筆。

## 不在這次範圍

- 備註改為底部面板或其他呈現方式。
- 分類網格的尺寸與列數（UX-001）。
- 金額欄改用系統鍵盤（UI-SPEC §5.5 規定金額維持自製鍵台）。

## 人類決定（2026-10-23）

1. 備註失焦後、內容是空的：**不自動收合**（照提案）。
2. 鍵盤的「完成」：**只收鍵盤，不送出**（照提案）。
3. 英文長名稱：依 UX-001 的人類決定（先照原樣放，放不下就提出較短的替代文字）。
