## 現況問題

UX-002 實作完成後，在 emulator（360×760dp）按「+備註」並開啟鍵盤，分類網格只剩約一列半：第一列完整，第二列的色塊露出但名稱被切掉，看起來像破圖（見 `docs/design/assets/UX-002-week-subtotal.webp` 第 3 張）。矮手機（例如 360×640dp）會更糟。

原因：UX-002 的高度預算以鍵盤頂端約 487dp 估算，實測約 470dp（含輸入法建議列）；加上「記一筆」實際高約 40dp、備註欄 56dp，兩列網格（約 160dp）缺約 40dp。

這個結果符合 UX-001／UX-002 寫的壓縮規則（網格退回較少列並可捲動），但「切在名稱中間」的呈現不是設計意圖。

## 決定

備註欄聚焦時，分類區分兩層處理，依「鍵盤上方實際可用的高度」自動切換，**不用螢幕尺寸判斷**。其他狀態（備註未聚焦）不變，仍是 UX-001 的兩列網格。

### 一般情況：單列橫向捲動（`LazyRow`）

1. 格子沿用現有樣式：50×50dp 色塊、圓角 16dp、11sp 名稱、選取態 2.5dp 分類色外框＋名稱 W700。
2. 每格寬 68dp（含內距），格間距 8dp，左右內距 20dp。360dp 寬的裝置上可見 4 個完整格加約半格（約 36dp），半格作為「還能橫向捲」的提示，**不加漸層遮罩**（人類決定 2026-10-28）。
3. 進入聚焦時：若選中的分類不在可見範圍，捲動到使它可見（`animateScrollToItem`，只在需要時捲動，不要每次都捲到最前面）。尚未選分類時不捲動。
4. 點任一格即選分類，行為與網格相同；**點選分類不改變備註欄焦點與鍵盤狀態**（鍵盤不收起）。
5. 順序與 UX-003 一致（依 `sortOrder`），單列只是同一個清單的橫向排列。

| 區塊 | 高度 |

| 狀態列 | 24 |
| 標題列 | 48 |

| 日期／備註列 | 56 |
| 備註欄 | 56＋下距 8 |
| 「記一筆」（按鈕約 40＋內距 8） | 約 48 |

### 矮手機：分類收成摘要列（人類決定 2026-10-28：做法 3）

當上表的內容高度（約 384dp）大於鍵盤上方的可用高度時（例如 360×640dp，鍵盤上緣約 350dp，缺約 34dp），改用較緊湊的版面：

1. **分類區收成一條摘要列**：高 48dp（列距 8dp），整條可點。左側為選中分類的 32×32dp 色塊（2dp 分類色外框）＋名稱（W700）；右側小字「更換」加向右箭頭圖示。尚未選分類時，左側顯示「選擇分類」（見「文字」）。
2. **點摘要列**：清除焦點、收起鍵盤，回到完整的兩列網格（鍵盤收起後空間足夠）。備註文字保留，備註欄維持展開。使用者選好分類後再點備註欄，又會進入聚焦狀態。
3. **金額區改為單行**，高 36dp：左側「{錢包名} · {幣別}」（`caption`，13sp，`onSurfaceVariant`），右側金額，字級用既有 token `donutTotal`（27sp／W600），**不新增 token**。整個金額區仍可點（`Role.Button`），點了清除焦點、收起鍵盤、數字鍵台回來（同 UX-002）。
4. **備註欄高度由 56dp 降為 48dp**（圓角 12dp、聚焦 2dp `primary` 外框不變）。

兩層之間的切換，以及單列與兩列之間的過渡，用預設動畫（`animateContentSize` 或 `AnimatedContent`），避免瞬間跳動；動畫尊重系統的移除動畫設定。

### 狀態

- 備註未聚焦：兩列網格（UX-001）。
- 備註聚焦、鍵盤上方高度足夠：單列橫向捲動；已選分類時選中項可見，未選時從第一格開始。
- 備註聚焦、鍵盤上方高度不足：摘要列；已選分類顯示該分類，未選分類顯示「選擇分類」。
- 載入中／空狀態／錯誤：不適用。深色模式與英文介面：沿用既有 token；英文名稱照 UX-001 已定案的用字（例如 Leisure）。

## 行為改變

資料不變，`TESTCASES.md` 沒有測案受影響。使用者在備註聚焦期間仍可換分類：一般手機直接點單列的格子；矮手機要先點摘要列（會收起鍵盤）。需要實作那邊確認的 Maestro flow：若有 flow 在備註聚焦期間斷言或點選「第二列」的分類，現在它們可能在橫向捲動範圍之外，或在矮手機被摘要列取代，需重跑確認。

## 無障礙

- 單列每格可點區域 68×76dp，大於 48×48dp；`Role.Button` 並帶 `selected` 狀態。
- 橫向捲動的清單由 TalkBack 的捲動動作操作；分類名稱已是每格的文字，順序與網格相同。
- 摘要列整條高 48dp、寬為整列，`Role.Button`，無障礙描述如上。
- 摘要列選中分類的色塊外框用分類色，名稱為 W700，不只靠顏色；「更換」與圖示色 `onSurfaceVariant`，對淺色背景約 4.7:1，深色約 7:1。
- 對比沿用 UX-001（名稱約 21:1，分類色外框 ≥ 3.9:1）。

## 不在這次範圍

- 備註改為底部面板或其他呈現（UX-002 已列為不在範圍）。
- 兩列網格本身的尺寸與列數（UX-001）。
- 備註未聚焦時的版面（沿用 UX-001）。

## 待決定

1. **兩層切換的判斷門檻。** 提案是以「鍵盤上方實際可用高度是否放得下單列版面（約 384dp）」判斷，並留一點緩衝。實作時請在 360×760、360×640 與另一個中間高度（例如 360×700）的裝置實測，確認不會在臨界高度來回閃爍；若判斷方式有技術困難，由實作那邊提出替代做法，交給人類決定。
2. **摘要列在鍵盤上方高度剛好足夠時的取捨。** 若某個中間高度的裝置只比 384dp 少很少（例如不到 10dp），是否值得為此切到摘要列，還是接受單列貼著鍵盤。提案是切換（避免「記一筆」被蓋住），但這取決於實測結果。
