設計畫布：https://claude.ai/artifact/Tw2d6cpLrfZksTkRW1ndNF 　對應最下一排的「做法 B｜卡片隨列表捲走（已捲動）」與「首頁｜日小標題＋完整預算卡」；英文版見「English｜日小標題長度檢查」。
這一項來自人類在設計討論中提出的兩件事：預算卡佔掉列表空間、想直接看到「今天花了多少」。

## 現況問題

1. 預算卡固定在列表上方，高約 200dp。360×760dp 的裝置上，標題列 56dp、底部導覽 84dp，列表可視高度只剩約 380dp，約 6 列。記錄一多，使用者大部分時間都在看一個小視窗捲動。
2. 列表只有「週」這層分組。想知道「今天花了多少」得自己把當天幾筆相加；每一列又都重複顯示日期（例如「10/27」），資訊重複卻沒有幫助。

## 決定

人類選擇「預算卡隨列表捲走」（人類決定 2026-10-28，畫布上的做法 B）；另見文末「人類決定」。

### 1. 預算卡成為列表的第一項

1. `BudgetCard` 從列表外的固定區移進同一個 `LazyColumn`，作為第一個 `item`；外觀、內容、尺寸與 UI-SPEC §4.2 完全相同，不改。
2. 標題列（錢包切換、設定）維持固定在最上方。
3. 捲動後預算卡會完全捲出畫面，列表可視高度約 596dp（360×760dp），比現況多約 216dp。代價：捲動後看不到餘額，回到頂端才看得到。
4. 預算卡與其下的週標題之間維持 12dp 間距（同現況）。

### 2. 週標題下新增「每日小標題」

1. 結構：週標題（不變）→ 該週內每一天一段：日小標題＋該日的圓角卡片（內含當天所有列）。同一週的各天卡片之間距 8dp。日期新到舊，與現況排序一致。
2. 日小標題高 28dp：左側為日期文字，右側為當日合計。樣式沿用既有 `label`（12sp）、W500，顏色 `onSurfaceVariant`；合計為負時同色，為正時用既有收入色。**不新增 token。**
3. 日期文字格式：今天顯示「今天 · 10/28 週三」，昨天顯示「昨天 · 10/27 週二」，其餘顯示「10/26 週一」。英文為「Today · Wed 10/28」、「Yesterday · Tue 10/27」、「Mon 10/26」。
4. 當日合計與週小計同規則：收入減支出的淨額，帶正負號（沿用 §4.3 人類決定）。只有支出的日子顯示 -NT$330.00，只有收入的日子顯示 +NT$1,200.00。
5. 沒有任何交易的日子不顯示小標題（不插入空白天）。
6. 日卡片沿用 §4.3 的列樣式（圓角 16dp、`HorizontalDivider`、左滑刪除、點擊進編輯、最小高 44dp）。

### 3. 跨年時插入「年份分隔列」

1. 列表由新到舊，當相鄰兩個日小標題的年份不同時，在兩者之間插入一列年份分隔，內容為較舊那一側的年份，例如「2026」。畫布「跨年｜年份分隔」：1/3（今年）之後插入「2026」，再接 12/30。
2. 最上方第一組若不是今年（例如今年沒有任何記錄），列表最上方也顯示一次該年份。
3. 年份分隔列高 32dp，不可點；左側年份文字 12sp、W700、顏色 `onSurface` 的次級色（沿用既有 token），右側一條 1dp 細線延伸到列尾。**不顯示該年合計。不新增 token。**
4. 週標題與週小計不變。跨年那一週（例如 12/28–1/3）仍是同一週、同一個小計，年份分隔列插在該週內部，不拆週。
5. 同一年內的記錄不會出現年份分隔。日小標題本身仍只寫「M/D 星期」，不帶年份。

### 4. 列內容：移除日期

有了日小標題，列的第二行不再顯示「M/D」。第二行只在有備註時顯示備註（原本是「M/D · 備註」）。沒有備註的列為單行：分類名稱置中對齊色塊，列高仍由 38dp 色塊加上下各 11dp 內距決定（約 60dp），不變。

### 5. 列表底部多留 80dp

`LazyColumn` 加 `contentPadding(bottom = 80.dp)`，讓捲到底時最後一列離 FAB 與底部導覽有餘裕。人類實測目前最後一列不會被 FAB 蓋住，這是預防性的留白，不是修 bug；各裝置字級放大時才較可能出現遮擋。

### 高度預算（360×760dp，單位 dp，估算值，請實測）

| 項目 | 高度 |
|---|---|
| 狀態列 | 24 |
| 標題列 | 56 |
| 預算卡（頂端時）＋下距 | 200＋8＋12 |
| 底部導覽 | 84 |
| 捲動後的列表可視高度 | 約 596 |
| 一天一段的額外成本 | 日小標題 28＋卡片間距 8＝36 |
| 跨年處的額外成本（僅出現一次） | 年份分隔 32 |

以畫布的範例資料（本週 4 筆、分布在 3 天）：頂端時 週標題 28＋3 個日小標題＋4 列，約 376dp，剛好塞滿約 380dp 的可視區；多於此就要捲動。

### 狀態

- 載入中：不適用（資料在本機）。
- 空狀態（沒有交易）：沿用 §4.3 的 📝 空狀態；預算卡仍在列表第一項，空狀態置於其下。
- 超支：預算卡內容沿用 §4.2 現有的超支呈現，只是位置改變。
- 刪除後該日只剩一筆或零筆：該日卡片列數減少；零筆時整段（含日小標題）消失；該週零筆時週標題也消失（同現況）。
- 跨年：年份分隔列見決定 3；整份記錄沒有跨年時不會出現。
- 深色模式、英文介面：沿用既有 token；英文日小標題見畫布，「Yesterday · Tue 10/27」在 360dp 寬仍可單行容納。

## 行為改變

資料與計算不變。`Budget.netTotal` 目前用於週小計，日小計可重用同一個函式，只是分組單位由週改為日；請實作那邊確認「日」與「週」的邊界用同一個時區與週起始日規則。

預算卡進入 `LazyColumn` 後，`HomeScreen` 的列表測試與 Maestro flow 若有「從螢幕頂端往下找第一個 transaction-row」的假設，需要確認：預算卡現在佔掉列表頂端，第一列 `transaction-row` 在畫面中的位置會往下移，在矮螢幕上可能不在首屏。請重跑 E2E 確認。

另外，目前每個週的卡片是一整張；改為每天一張後，`testTag("transaction-row")` 的總數不變，但「同一張卡片」的假設會改變，若有測案以卡片為單位計數需調整。

## 文字（繁中／英文）

| 位置 | 繁中 | English |
|---|---|---|
| 日小標題（今天，新增，{日期} 如 10/28，{星期} 如 週三） | 今天 · {日期} {星期} | Today · {星期} {日期} |

「今天」「昨天」目前在記帳頁已有字串（日期選項），若可重用請重用，避免重複。

## 無障礙

- 年份分隔列標為 heading，朗讀為「2026 年」／ "2026"；細線不朗讀。
- 日小標題標為 heading（`semantics { heading() }`），TalkBack 可用標題導覽在各天之間跳動。
- 日小標題的無障礙描述把左右兩段合成一句：「今天，10月28日週三，淨額負 330 元」／ "Today, Wednesday October 28, net minus NT$330"，不要分成兩次朗讀。
- 對比：12sp `onSurfaceVariant`（#6B6B70）在背景 #F2F1EF 上約 4.6:1，達 4.5:1；深色沿用既有 token，請實作那邊用既有的對比檢查確認。正數用既有收入色並以「+」號輔助，不只靠顏色。
- 列的點擊區域（高 ≥ 44dp）、滑動刪除的行為不變。

## 不在這次範圍

- 預算卡的內容與尺寸（§4.2）不變。若日後想把「今天已花」放進預算卡，另開一單。
- 刪除的可發現性與 TalkBack 自訂動作（首頁列表審查項目 3）。
- 刪除後出現空白列（疑似 `rememberSwipeToDismissBoxState` 未以交易 id 為 key），這是 bug，不是設計決定，請另行處理。

## 人類決定（2026-10-28）

1. 當日合計用淨額（收入減支出），與 §4.3 週小計一致。
2. 當天沒有交易時不顯示日小標題，不顯示「今天 · NT$0」。
3. 日小標題不吸頂。
4. 日小標題與日期圖示不顯示年份，沿用「M/D」；跨年時在列表中插入年份分隔列（人類提議，2026-10-28）：不拆週、不顯示該年合計。
5. 捲動後看不到餘額可以接受，採用做法 B，試用一陣子再評估；若不便，用新編號取代為精簡卡（畫布做法 C）。
6. 列表底部多留 80dp（`contentPadding`），預防最後一列被 FAB 遮住。
