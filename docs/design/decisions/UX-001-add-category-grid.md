## 現況問題

截圖 04：分類網格只露出第一列 4 個，最常用的「飲食」在第二列，要先往上滑才看得到。截圖 06：開啟備註後網格被壓成半截。

原因（已對照 `AddEditTransactionScreen.kt`）：`CategoryGrid` 只拿到 `Modifier.weight(1f)`，也就是其他元件排完之後剩下的高度，而其他元件吃掉太多：

- 數字鍵台每鍵 `aspectRatio(1.6f)`，360dp 寬的裝置上每鍵約 67dp 高，整個鍵台約 315dp。
- 金額區上下各 `padding(24.dp)`。
- 日期 pill 為 `heightIn(min = 36.dp)`，低於 UI-SPEC §1.2 的 48dp。

剩給網格的高度約 70dp，剛好一列。UI-SPEC §5 已經規定是 4 欄 `LazyVerticalGrid`，問題不在規格，在版面高度預算。

## 決定

在 **360×760dp** 的裝置上，分類網格一次完整露出 **2 列（8 格）**，7 個預設分類不需捲動。

1. 數字鍵台改為**固定鍵高 56dp**，取代 `aspectRatio(1.6f)`；鍵間距與圓角（12dp）不變。
2. 金額區上下 padding 由 24dp 改為 8dp。
3. 日期／備註 pill（`FilterChip`）最小高度由 36dp 改為 **48dp**。
4. 分類網格預留 2 列高度。分類超過 8 個時，在網格內垂直捲動，第三列露出約半列作為可捲動提示。
5. 螢幕高度不足時，壓縮優先順序：金額區 padding → 鍵台鍵高（不低於 48dp）→ 最後才讓網格退回「可捲動」。

高度預算（360×760dp，單位 dp；估算值，請在 emulator 實測，並另測一台較矮的裝置，例如 360×640）：

| 區塊 | 現況 | 提案 |
|---|---|---|
| 狀態列（系統 inset） | 24 | 24 |
| 標題列 | 48 | 48 |
| 金額區 | 約 130 | 約 98 |
| 分類網格 | 約 70（1 列） | 約 156（2 列，每列約 76＋列距 4） |
| 日期／備註列 | 約 48 | 約 56 |
| 數字鍵台 | 約 315 | 約 272（4×56＋3×8 間距＋上下 12） |
| 「記一筆」區（按鈕＋padding＋手勢列 inset） | 約 80 | 約 80 |
| 合計 | 約 715，網格被壓縮 | 約 734，網格有約 26dp 餘裕 |

沿用 UI-SPEC 既有 token，**不新增 token**：

| 項目 | 值 | 出處 |
|---|---|---|
| 欄數 | 4（`GridCells.Fixed(4)`） | §5.3 |
| 分類色塊 | 50×50dp、圓角 16dp，底色為分類色套 `categoryTintAlpha`（light 12%、dark 18%） | §2.2、§5.3 |
| 分類名稱 | 11sp，單行 | §5.3 |
| 選取態 | 2.5dp 分類色外框；**名稱字重改 W700**（唯一新增） | §5.3 |
| 格內距 | 6dp（沿用現況） | 程式碼現況 |
| 鍵台鍵 | 高 56dp、圓角 12dp、底色 `key` | §2.4、§2.1 |
| 日期／備註 pill | 最小高 48dp | §1.2 |

狀態：

- 預設（未選分類）：所有格子為未選取樣式，「記一筆」disabled（金額為 0 時本來就 disabled）。
- 選中：2.5dp 分類色外框＋名稱 W700。
- 載入中／空狀態／錯誤：預設分類由 `seedDefaults()` 建立，記帳頁不會出現沒有分類的情況，本次不新增這三種狀態。
- 深色模式：色塊底色改用 dark 的 18% 透明度，其餘不變。
- 英文介面：沿用同一版面；名稱較長時的處理見「人類決定」。

選取態的名稱加粗是對 UI-SPEC §5.3 唯一的補充。理由：外框用的是分類色本身（例如「其他」是灰色），色盲使用者無法只靠外框顏色分辨選中項。

## 行為改變

沒有改變使用者能做的事與資料，`TESTCASES.md` 沒有測案受影響。受影響的是 `.maestro/E2E-1-first-launch.yaml`：它有一段 `swipe` 專門為了滑到被裁掉的「飲食」（註解寫明是排序加裁切造成），本決策與 UX-003 完成後這段不再需要，應改成直接 `assertVisible: "飲食"`。`E2E-10-stats.yaml`、`E2E-14-language.yaml` 也用到「飲食」，位置改變後需重跑確認。

## 無障礙

- 分類格整格可點，高度約 76dp、寬度約 80dp，皆大於 48×48dp。
- TalkBack：每格 `Role.Button`，並帶 `selected` 狀態；選取不能只靠視覺。
- 名稱 `onSurface`（dark `#FFFFFF`）對 `#000000` 約 21:1，遠高於 4.5:1。
- 分類色外框對深色背景 `#000000` 的對比（估算）：飲食 4.4、交通 5.3、居住 5.4、購物 3.9、娛樂 4.5、醫療 4.5、其他 4.9，皆 ≥ 3:1（非文字元件的標準）。

## 人類決定（2026-10-23）

1. 分類超過 8 個時：**維持「2 列＋網格內捲動」**（照提案）。
2. 英文長名稱：**先照原樣放**；實作時在 emulator 實測，若 11sp 單行放不下，由實作那邊**提出較短的英文替代文字**給人類選（例如 Entertainment 的替代詞），不改版面、不縮字級、不換行。
3. 「＋新增分類」入口：**不做**（照提案）。

## 實作時的發現與人類決定（2026-10-24）

在 emulator 用 360×760dp（基準尺寸）實測：

1. **兩列放不下**：設計的高度預算是估算值，實際上分類網格只分到約 118dp（兩列需要約 164dp）。
   依 UI-SPEC §5 的壓縮順序，內容高度不足 740dp 時鍵高改為 48dp、「記一筆」上下內距由 20dp 改為 8dp，兩列就完整露出；
   較高的手機維持 56dp 鍵高。
2. **英文長名稱**：「Entertainment」在 360dp 會被切成「Entertainmen」。人類決定改為 **「Leisure」**（繁中「娛樂」不變）。
3. **英文日期／備註 pill 放不進一列**（「+ Note」被擠成三行）。人類決定：「選日期」pill **改成只放日曆圖示**
   （繁中、英文都改；無障礙描述仍是「選日期」／"Pick date"；選了其他日期後照舊顯示「M/D」）。
   **這是版面改動，下一次設計討論要確認**——見總表的「待設計討論」。
